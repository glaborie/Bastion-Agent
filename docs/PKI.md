# East-West PKI Runbook (ADR-019)

The `pki` profile turns the internal bridge from password-authenticated to
certificate-authenticated for PostgreSQL, Redis and Keycloak. The default stack
is unchanged and stays plaintext, loopback-only and local-only.

Everything below assumes the repository root and Docker Compose v2.

## 1. Bootstrap the CA material

```bash
./scripts/pki/bootstrap.sh
```

This creates `secrets/ca_password` and `secrets/provisioner_password` (mode
`0600`, random) and the `pki/` tree. Both paths are gitignored. The CA root key
is generated by the next step and lives only in `pki/ca/secrets/`.

## 2. Start the profile

```bash
docker compose -f docker-compose.yml -f docker-compose.pki.yml \
    --profile pki up -d
```

Order: `pki-init` (one-shot `step ca init`), `ca` (Step-CA on `https://ca:9000`,
no host port), `pki-issue` (issues every leaf), then the services. `pki-issue`
exits after issuance; re-run it to renew.

## 3. Prove PostgreSQL refuses a password and a plaintext connection

With the profile up, from a container on the same network (the client certificate
is `pki/gateway/tls.crt`; the CN is the database role):

```bash
docker run --rm --network bastion-agent_bastion-net -v "$PWD/pki:/pki:ro" \
  -e PGPASSWORD=dummy postgres:16.15-alpine \
  psql "host=db port=5432 dbname=bastion user=bastion sslmode=verify-full \
        sslrootcert=/pki/trust/ca.crt sslcert=/pki/gateway/tls.crt \
        sslkey=/pki/gateway/tls.key" -tAc 'select 1'
# -> 1

# Same command without sslcert/sslkey (a password is not enough):
# -> FATAL: connection requires a valid client certificate

# Same host, no TLS at all:
# -> FATAL: pg_hba.conf rejects connection for host "...", user "bastion",
#           database "bastion", no encryption
```

From the host, the same check works against the published loopback port when the
certificate files are readable by your user (`pki/gateway` is owned by the
container uid, so copy the pair out or run the client in a container).

## 4. Prove Redis has no plaintext path

```bash
# With a client certificate:
docker run --rm --network bastion-agent_bastion-net -v "$PWD/pki:/pki:ro" \
  redis:7-alpine redis-cli -h redis --tls --cacert /pki/trust/ca.crt \
  --cert /pki/gateway/tls.crt --key /pki/gateway/tls.key \
  -a "$REDIS_PASSWORD" --no-auth-warning ping
# -> PONG

# Without one: the server closes the connection (I/O error).
```

Redis listens on `--tls-port 6379 --port 0`, so there is no plaintext port to
fall back to.

## 5. Prove Keycloak serves HTTPS

```bash
docker run --rm --network bastion-agent_bastion-net -v "$PWD/pki/trust:/pki:ro" \
  curlimages/curl:8.11.1 -sS --cacert /pki/ca.crt -o /dev/null -w '%{http_code}\n' \
  https://keycloak:8080/realms/bastion/.well-known/openid-configuration
# -> 200; without --cacert the TLS handshake fails
```

The gateway trusts this CA for JWKS and token calls through
`OIDC_CA_CERT_PATH=/pki/ca/ca.crt`, set by the profile.

## 6. Renew

```bash
docker compose -f docker-compose.yml -f docker-compose.pki.yml \
    --profile pki up -d --force-recreate pki-issue
```

Every leaf is re-issued with a fresh serial and `notAfter` (lifetime from
`PKI_CERT_TTL`, default `24h`). PostgreSQL reloads on `SIGHUP`:

```bash
docker kill -s HUP bastion-agent-db-1

openssl s_client -starttls postgres -connect 127.0.0.1:5432 \
  -servername db -CAfile pki/trust/ca.crt </dev/null 2>/dev/null \
  | openssl x509 -noout -serial -enddate
```

Capture that output before and after the renewal; the serial must change. Redis,
Keycloak and the application processes read their certificate at start or
connection time and need a restart.

## 7. Tear down

```bash
docker compose -f docker-compose.yml -f docker-compose.pki.yml \
    --profile pki down
# Remove the CA and every leaf:
rm -rf pki secrets
```

## Limits to keep in mind

- The CA root key is on the host it protects. Host or root compromise defeats
  this control; the gain is against credential replay from another workload.
- A missing certificate or CA bundle fails closed at startup. A CA that is
  unreachable at issuance time means services start from their last cached leaf.
- OmniRoute and the OTLP endpoint are still plain HTTP; `pgadmin` and `redis-ui`
  are excluded from the profile.
- There is no revocation list: a stolen leaf is valid until `notAfter`.
