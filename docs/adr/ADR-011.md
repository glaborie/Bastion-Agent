# ADR-011: ONNX Semantic Sensitivity Classifier

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-09

## Context

ADR-002 splits confidentiality handling into two stages: deterministic identifier redaction (Presidio) and a semantic decision about whether a prompt may leave the perimeter at all. ADR-004 binds that decision to routing — `CONFIDENTIAL` traffic goes to the local `llama.cpp` model, `PUBLIC` traffic may go to a cloud provider through OmniRoute. Milestone 3 shipped `agent/routing/classifier.py` with a weighted semantic-rule fallback and an optional single-graph ONNX contract that returns two logits ordered `[PUBLIC, CONFIDENTIAL]`. That contract answers exactly one question — is this text sensitive? — and cannot express anything else.

Two different risks are being conflated by that single bit. The first is **disclosure**: a prompt contains client identifiers, balances, contracts or internal strategy, and must not reach a third party. The second is **prompt injection**: the carrier is hostile — a system-prompt extraction attempt, an instruction planted mid-context, a refusal-suppression payload — and every follow-on action is attacker-controlled regardless of how sensitive the words are. Explicit rules catch identifier formats and marking words such as "confidential", but not paraphrase ("our client's account at the Zürcher Kantonalbank"), and they catch no indirect injection at all, because the payload arrives inside tool output rather than user text. Presidio stays the authoritative stage for identifiable data; the second stage has to be a model that generalises.

The deployment budget constrains the choice as much as the task does. The RTX 3060 Ti has 8 GB of VRAM, of which the Q4_K_M 7B local model already claims roughly 4.7 GB, so the classifiers must fit in the remainder and add under 50 ms to a request. The graphs must run on CPU through the same contract when no GPU is present, must be quantised to keep memory flat under concurrent requests, and must be licensed for commercial use in Switzerland. The corpus is mixed German, French, Italian and English.

## Decision

1. **Adopt a two-model ONNX ensemble, evaluated in a fixed order, instead of extending the single-graph contract.** Each model answers one question, is tuned independently, and can be replaced without retraining the other.

   | Model | Question it answers | ONNX repository | Size (int8) | Warm latency (RTX 3060 Ti) | Licence |
   |-------|--------------------|-----------------|-------------|---------------------------|---------|
   | Safety guard | Is this content unsafe, and in which category? | `onnx-community/content-safety-guard-small-ONNX` | ~268 MB | ~15–25 ms | Apache-2.0 |
   | Injection guard | Is this text trying to manipulate the model? | `onnx-community/prompt-injection-guard-small-ONNX` | ~268 MB | ~10–15 ms | Apache-2.0 |

2. **The safety guard supplies the sensitivity verdict.** It returns an aggregate `unsafe` score plus 15 harm categories, including `privacy`, `fraud_manipulation`, `criminal_planning` and `unauthorized_advice`. Routing reads the aggregate and four categories: `unsafe >= 0.5` marks the prompt `CONFIDENTIAL` and flags it for review; any of the four categories at `>= 0.3` marks it `CONFIDENTIAL` with that category recorded as the reason. The remaining categories are logged for triage, not routed on, until the golden dataset justifies a threshold for them.

3. **The injection guard is evaluated first and cannot be overridden.** Direct and indirect injection — mid-context override, system-prompt extraction, refusal suppression — are scored into a single `injection_prob`. The production threshold is `0.662`; a `recall-first` profile lowers it to `0.5` for high-risk tenants and offline scanning. Any score at or above the active threshold routes `CONFIDENTIAL` with the reason `prompt_injection_detected`, and the request never falls back to a cloud provider.

4. **Routing is the conjunction of both verdicts.** A prompt is public only when the injection guard is below threshold *and* the safety categories are below threshold:

   | Condition | Route | Reason code |
   |-----------|-------|-------------|
   | `injection_prob >= 0.662` (or `0.5` in recall-first) | `local-llama` | `prompt_injection_detected` |
   | `unsafe >= 0.5` | `local-llama` | `unsafe_content` |
   | `privacy >= 0.3` | `local-llama` | `privacy_risk` |
   | `fraud_manipulation >= 0.3` | `local-llama` | `fraud_manipulation` |
   | `criminal_planning >= 0.3` | `local-llama` | `criminal_planning` |
   | `unauthorized_advice >= 0.3` | `local-llama` | `unauthorized_advice` |
   | All below threshold | `cloud-primary` | `public_content` |

5. **Both models fail closed.** An ONNX session error, a missing graph, a missing tokenizer or a malformed output resolves to `CONFIDENTIAL`. Locally (`ENVIRONMENT=local`) the existing rule classifier remains as a documented fallback so the demo runs without models; in every other environment a missing model aborts startup with `ClassifierConfigurationError` rather than silently degrading the gate.

6. **One interface, two graphs.** The decision extends `agent/routing/classifier.py::SensitivityClassifier.classify(text) -> Classification`, keeping the frozen `Classification(label, confidence, model, matched, reason)` value object that ADR-004 already consumes. Sessions are opened once per process with `CUDAExecutionProvider` first and `CPUExecutionProvider` as the fallback, and the graph paths, token limits and all thresholds come from settings:

   ```python
   @dataclass(frozen=True, slots=True)
   class Classification:
       label: Sensitivity       # PUBLIC | CONFIDENTIAL
       confidence: float        # score of the deciding model
       model: str               # "injection-guard" | "safety-guard" | "rules"
       matched: tuple[str, ...] # harm categories or rule names
       reason: str              # stable reason code from the table above


   class SensitivityClassifier:
       def __init__(self, settings: Settings) -> None:
           self._injection = _OnnxModel(settings.injection_model_path, ...)
           self._safety = _OnnxModel(settings.safety_model_path, ...)

       def classify(self, text: str) -> Classification:
           injection = self._injection.predict(text)
           if injection.probability >= settings.injection_threshold:
               return Classification(CONFIDENTIAL, injection.probability,
                                     "injection-guard", (), "prompt_injection_detected")
           safety = self._safety.predict(text)
           ...  # decision table above, fail closed on error
   ```

7. **Thresholds are configuration, not constants, and are tuned against the golden dataset.** `0.662`, `0.5` and `0.3` are starting points measured on the model cards' own evaluation sets; they are only defensible once ADR-006's golden set covers Swiss German/French/Italian paraphrase, benign banking vocabulary and known injection payloads. Every threshold change re-runs the evaluation gate, and the chosen values are recorded with the run id in this ADR's change history.

8. **Models are mounted, never baked and never fetched at runtime.** The gateway and worker read `models/` as a read-only volume; the image stays small and a model swap does not rebuild it. Each graph's SHA-256 is pinned in `.env.example` and verified at startup, so an operator cannot silently run a different quantisation.

9. **The audit trail records reason codes, never prompt text or raw scores.** `metadata_json` carries the reason code, the deciding model name and the threshold that fired, consistent with ADR-005's rule that the ledger must not accumulate prompt content.

10. **This complements the Milestone 5 canary tripwire rather than replacing it.** The injection guard is prevention: it stops a payload before egress. The session canary is detection: it proves whether content leaked despite the gate. A router that claims prevention without a tripwire has no way to know it failed.

## Consequences

- **Pros**: Two narrow models are easier to evaluate and replace than one combined graph; injection detection exists at all, which the single-graph contract could not express; identifier redaction stays deterministic in Presidio while only the semantic judgement is learned; ~25–40 ms combined warm latency fits the 50 ms budget and leaves the GPU usable for inference; Apache-2.0 on both graphs permits commercial deployment; the frozen `Classification` interface means routing, telemetry and tests do not change.
- **Cons**: Two graphs plus two tokenizers roughly double the classifier memory (~536 MB) and contend with the local model for an 8 GB GPU, so VRAM headroom must be measured, not assumed; int8 quantisation costs some recall on nuanced paraphrases, which is why the recall-first profile exists; 15 categories invite over-routing if operators lower thresholds without data, so threshold changes are gated on the golden dataset; the models are upstream artefacts with their own release cadence, so digest pinning and an update procedure are mandatory; the rules-only fallback can never detect injection, so the ensemble is a production requirement rather than an optimisation.

## Rollout

The decision is accepted; the ensemble is not yet wired into the running router. `agent/routing/classifier.py` currently ships the rule fallback and the single-graph contract, and the gateway does not import any prototype classifier. Remaining work, in order:

- [ ] Fetch both repositories into `models/` (see Verification) and record digests in `.env.example`.
- [ ] Add `injection_model_path`, `safety_model_path`, `injection_threshold`, `injection_profile` and the category thresholds to `settings.py`, with startup validation and digest checks.
- [ ] Implement the two-session classifier behind the existing `classify()` signature; keep the rule fallback for `ENVIRONMENT=local`.
- [ ] Extend `tests/test_classifier.py` with per-category cases, injection payloads and fail-closed paths.
- [ ] Add golden cases for the four categories and injection to ADR-006's dataset, then tune thresholds and record the winning values here.
- [ ] Mount `models/` read-only on `gateway` and `worker`; confirm VRAM headroom alongside `llama.cpp`.
- [ ] Re-run the DREAD table in `THREAT_MODEL.md` for prompt injection (direct and indirect) once the gate is live.

## Verification

```bash
# Fetch both repositories (the whole repo; internal ONNX paths are not assumed)
uvx --from huggingface_hub hf download \
  onnx-community/content-safety-guard-small-ONNX \
  --local-dir models/content-safety-guard-small
uvx --from huggingface_hub hf download \
  onnx-community/prompt-injection-guard-small-ONNX \
  --local-dir models/prompt-injection-guard-small

# Deterministic classifier tests (no model required)
uv run pytest -q tests/test_classifier.py
```

Acceptance for the wired ensemble: an injection payload routes to `local-llama` with `prompt_injection_detected`; a request naming a client's IBAN routes to `local-llama` with `privacy_risk`; a public question routes to `cloud-primary`; a missing graph in a non-local environment aborts startup; combined warm latency stays under 50 ms with `llama.cpp` resident.
