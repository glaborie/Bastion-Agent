# ADR-023: Local PDF Ingestion with DLP Redaction Before the Model

**Status:** Accepted
**Date:** 2026-11-17
**Last modified:** 2026-11-17

## Context

The chat endpoint accepts text only: `ChatRequest` carries `ChatTurn.content: str`
and nothing in `gateway/routers/` reads a multipart body, so a PDF reached the
model only by copy-paste or through a converter outside the perimeter, where its
unredacted text never met `PresidioDLP.redact()` and left no trace. The obvious
library is not a redaction step either: `markitdown` sends the raw document to
Azure Document Intelligence when a `docintel_endpoint` is configured, and its OCR
package requires an `llm_client`, so both options put the whole file in front of a
model before any entity is replaced.

The missing piece is therefore a one-way gate rather than a conversion call:
extraction has to happen inside the perimeter, and the text has to be redacted
before it exists anywhere else. Two constraints bound how far that gate can go in
one slice. The repository ships a single supported deployment (one Compose stack),
so a sandboxed converter service is a new process, image and policy surface for a
command an operator runs by hand. And the parser is an untrusted-binary parser:
no size limit, format allow-list or timeout makes a parser vulnerability
impossible, which has to be said rather than implied.

## Decision

1. **One operator command, no new surface.** `python -m agent.ingest.cli convert`
   runs inside the gateway image or the host checkout. No
   gateway route, compose service, tool-catalog entry or required `.env` key is
   added: `grep -rn "markitdown" docs/tools/v1.json docker-compose.yml gateway/`
   stays empty.

2. **PDF is the only accepted input, checked twice.** The suffix must be `.pdf`
   and the bytes must start with `%PDF-`; an encrypted file, a file over
   `DOCUMENT_MAX_BYTES` (20 MB) or one that yields no text exits non-zero. The
   artifact is written only after the whole conversion and redaction succeed, so a
   failure leaves an existing output path untouched.

3. **The extractor is pinned and closed.** `markitdown[pdf]` — the narrow extra,
   not `[all]` — with `MarkItDown(enable_plugins=False)` and no `docintel_*`
   argument and no `llm_client`, so neither Document Intelligence nor OCR can be
   reached from this path. There is no settings key for any of them. Extraction
   runs in a worker thread under `DOCUMENT_PARSE_TIMEOUT_SECONDS` (30 s), so a
   pathological file cannot block the event loop.

4. **Redaction is the shipped stage, not a second implementation.**
   `PresidioDLP.redact()` is called with `tenant_id` and the session
   `ingest:<sha256(tenant ‖ actor ‖ sha256(file))>`, so the markers are the same
   markers chat produces, two documents cannot share them, and another tenant or
   session cannot restore them. Markers stay restorable for
   `VAULT_TTL_SECONDS` (1800 s); after that the command reports the markers as
   expired rather than printing them unchanged.

5. **Metadata and attachments never reach the artifact.** Only `text_content`
   from the conversion is used, so `/Author`, `/Title` and embedded files do not
   appear. The run writes one structured log line — extractor, page count, entity
   counts and entity types — and nothing else: no new `AuditEventType` member,
   because ADR-007 decision 7 keeps the ledger vocabulary frozen and a conversion
   is an operator action rather than a request-path event.

6. **De-identification is not declassification.** The README states the boundary:
   a redacted document is still confidential by content, the classifier still
   decides its route, and DLP recall bounds what the markers cover. An
   out-of-vocabulary name or a postal address behaves here exactly as it does in
   chat.

## Consequences

**Pros**

- One PDF can enter the pipeline with every detected entity already a marker, and
  the artifact is auditable as a log line without storing the text twice.
- The extractor cannot reach a cloud service or a model, and the conversion cannot
  reach the network at all, because the adapter constructs it closed.
- The redaction, its markers and their scope are the ones the chat path already
  uses; there is no second policy to drift.
- The command is optional: nothing in the gateway, the worker or the compose stack
  depends on it.

**Cons**

- The parser runs in-process on an untrusted file. The size ceiling, allow-list
  and timeout bound resource use, not a parser vulnerability; a sandbox is a later
  decision.
- A scanned PDF is refused instead of being read, because OCR needs a model.
- A damaged PDF can still yield partial text: the zero-text check catches the
  empty case only, and a page-versus-character floor is not implemented.
- Markers restore for 30 minutes; after that the artifact is a one-way redaction
  and the operator has to re-convert the source.
- No audit row means the conversion is outside the hash-chained ledger; the log
  line is the only evidence that it happened.
