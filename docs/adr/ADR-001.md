# ADR-001: Core Ingress & Zero-Trust Gateway

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-12

## Context

Bastion-Agent must serve as the single, hardened entry point for all agent traffic. Every inbound request, outbound model call, and tool execution must pass through a controlled boundary that enforces authentication, authorization, DLP, and audit logging. There must be no direct agent-to-LLM or agent-to-tool connections that bypass the gateway.

The deployment target is a single Docker Compose stack on one host (WSL2 + Docker Desktop during development), with Keycloak as the only identity provider and no service mesh or sidecar proxies. That keeps the trust boundary small and auditable, at the cost of making the gateway a single point of failure and a latency bottleneck: every guardrail runs in-process and must stay cheap enough for interactive use.

**East-west amendment (2026-11-12, ADR-019).** "No sidecar proxies" is about the request path, and it still holds: nothing proxies a guarded call. It never meant that the bridge is a flat trusted network, and this ADR no longer implies it. The opt-in `pki` profile gives PostgreSQL, Redis and Keycloak mutual TLS with per-service certificates from a local Step-CA, so a shared password is no longer sufficient east-west; the default profile remains plaintext and loopback-only for local development. ADR-019 owns the trust model, the honest limit (a host-root attacker defeats a CA on the same host) and the parts still deferred.

## Decision

1. **Single FastAPI ingress**: All traffic routes through one FastAPI process. No peer-to-peer agent connections, no sidecar proxies, no external SDKs that circumvent the choke point. East-west transport identity is separate from this decision and lives in ADR-019; the `pki` profile's issuance job is a one-shot build step, not a proxy in the request path.

2. **OIDC RS256 validation at the gateway**: Keycloak access tokens are validated against a JWKS document fetched over the internal network and cached by `kid`, with a bounded refresh rate for unknown keys. Only `RS256` is accepted; `none`, HMAC and other algorithms are rejected *before* signature verification. Issuer, audience (`bastion-gateway`), `exp`/`iat`/`nbf` and a configurable clock leeway are always enforced. Roles are read from `realm_access.roles` and filtered to the four known roles, and the tenant is read from the configured `TENANT_CLAIM` (default `tenant_id`); a token without a valid tenant claim is rejected (ADR-015). Browser clients use the authorization-code flow with PKCE and keep tokens server-side in Redis; API clients present a Bearer token.

3. **Deterministic DLP first**: Microsoft Presidio + custom regex patterns run synchronously before any LLM sees the prompt. Entity redaction uses reversible AES-256-GCM token vault in Redis (30-min TTL).

4. **OmniRoute as the only routing layer**: The agent never calls an LLM directly. All model calls go through OmniRoute, which dispatches to local `llama.cpp` (Qwen 2.5 7B Q4_K_M on RTX 3060 Ti) for confidential prompts, or OpenRouter cloud providers for general prompts.

5. **Audit is synchronous and append-only**: Every event (input, redaction, routing decision, tool request, approval, egress) is written to PostgreSQL with SHA-256 hash chaining. No UPDATE/DELETE on `audit_logs`.

6. **Four-eyes HITL for writes**: Any `read_only=False` tool causes the ARQ worker (Milestone 4) to suspend execution, create a `PendingApproval` record, and return `approval_pending`. The approving user **cannot** be the initiator (`initiator_id != approver_id`). Milestone 2 already implements the dashboard decision side under a row lock and a database constraint.

## Consequences

- **Pros**: Zero-trust by construction; every action is auditable; DLP blocks leaks before they reach the model; human approval prevents accidental writes; single ingress simplifies compliance.
- **Cons**: Added latency from DLP + approval flow (mitigated by lightweight Presidio + ONNX classifier); operator overhead for HITL; requires disciplined tool declaration.
