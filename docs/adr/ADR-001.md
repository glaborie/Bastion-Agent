# ADR-001: Core Ingress & Zero-Trust Gateway

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-09

## Context

Bastion-Agent must serve as the single, hardened entry point for all agent traffic. Every inbound request, outbound model call, and tool execution must pass through a controlled boundary that enforces authentication, authorization, DLP, and audit logging. There must be no direct agent-to-LLM or agent-to-tool connections that bypass the gateway.

The deployment target is a single Docker Compose stack on one host (WSL2 + Docker Desktop during development), with Keycloak as the only identity provider and no service mesh or sidecar proxies. That keeps the trust boundary small and auditable, at the cost of making the gateway a single point of failure and a latency bottleneck: every guardrail runs in-process and must stay cheap enough for interactive use.

## Decision

1. **Single FastAPI ingress**: All traffic routes through one FastAPI process. No peer-to-peer agent connections, no sidecar proxies, no external SDKs that circumvent the choke point.

2. **OIDC JWT validation at the gateway**: Keycloak-issued RS256/ES256 tokens validated via JWKS cache. Roles (`admin`, `operator`, `analyst`, `readonly`) extracted and enforced declaratively on every tool.

3. **Deterministic DLP first**: Microsoft Presidio + custom regex patterns run synchronously before any LLM sees the prompt. Entity redaction uses reversible AES-256-GCM token vault in Redis (30-min TTL).

4. **OmniRoute as the only routing layer**: The agent never calls an LLM directly. All model calls go through OmniRoute, which dispatches to local `llama.cpp` (Qwen 2.5 7B Q4_K_M on RTX 3060 Ti) for confidential prompts, or OpenRouter cloud providers for general prompts.

5. **Audit is synchronous and append-only**: Every event (input, redaction, routing decision, tool request, approval, egress) is written to PostgreSQL with SHA-256 hash chaining. No UPDATE/DELETE on `audit_logs`.

6. **Four-eyes HITL for writes**: Any `read_only=False` tool causes the ARQ worker to suspend execution, create a `PendingApproval` record, and return `approval_pending`. The approving user **cannot** be the initiator (`initiator_id != approver_id`).

## Consequences

- **Pros**: Zero-trust by construction; every action is auditable; DLP blocks leaks before they reach the model; human approval prevents accidental writes; single ingress simplifies compliance.
- **Cons**: Added latency from DLP + approval flow (mitigated by lightweight Presidio + ONNX classifier); operator overhead for HITL; requires disciplined tool declaration.
