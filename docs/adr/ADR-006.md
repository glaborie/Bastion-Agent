# ADR-006: DeepEval Golden Dataset & Regression Gating

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-09

## Context

Every change to DLP rules, the sensitivity classifier, the egress filter, or the routing logic must be validated against a known set of golden test cases before merge. There must be a hard zero-tolerance gate: if any test case fails, the change does not pass CI.

Security regressions must be caught deterministically: a failing case has to fail the same way every run, so the security metrics are exact match / regex based rather than LLM-judged. The suite runs offline in CI with no provider credentials, which means golden cases exercise the local pipeline (DLP, vault, egress) rather than live model quality; that keeps the gate fast and reproducible at the cost of not measuring answer quality.

## Decision

1. **Golden dataset `tests/data/goldens.jsonl`**: JSONL with entries:
   ```json
   {
     "prompt": "<raw prompt>",
     "expected_redactions": ["{{ENTITY:PERSON_1}}", ...],
     "expected_route": "local-llama" | "cloud-primary",
     "expected_score": 1.0  -- DeepEval metric threshold
   }
   ```

2. **Test categories** (at least 25 entries):
   - PII variants: names, emails, phone numbers, IBANs, API keys across multiple formats.
   - Confidential IP: business-specific terms, project codenames, internal schemas.
   - Prompt injection / indirect prompt extraction: canary-triggering prompts, jailbreak probes.
   - Standard tasks: normal queries that should route to `cloud-primary` without redaction.
   - Borderline: prompts that test the sensitivity classifier's confidence threshold.

3. **Pytest + DeepEval suite** `tests/test_dlp_evals.py`:
   ```python
   @given(golden_prompts)
   def test_dlp_redaction(golden):
       result = deepeval.test_run(
           model_name="local-llama",
           prompts=[golden["prompt"]],
           metrics=[DLPRedactionMetric(golden["expected_redactions"])],
           threshold=1.0,
       )
       assert result.score == 1.0, f"DLP redaction failed: {result.failure_reason}"


   @given(golden_prompts)
   def test_egress_canary(golden):
       result = deepeval.test_run(
           model_name="local-llama",
           prompts=[golden["prompt"]],
           metrics=[EgressCanaryMetric()],
           threshold=1.0,
       )
       assert result.score == 1.0, f"Canary leak detected: {result.failure_reason}"
   ```

4. **CI integration**: `uv run pytest tests/test_dlp_evals.py -v` fails the pipeline on any score < 1.0.

5. **Local viewing**: `uv run deepeval view` opens the local HTML report for developers to inspect failures.

## Consequences

- **Pros**: Zero-tolerance gate catches regressions instantly; golden dataset serves as living documentation of expected behavior; `deepeval view` makes failures visible without running CI; easy to add new edge cases.
- **Cons**: Maintaining the dataset requires developer time; threshold `1.0` is strict but appropriate for security; adding new test categories as the system evolves.
