# ADR-007: Command Control Dashboard & HTMX Integration

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-09

## Context

Operators need a lightweight, always-available dashboard to monitor approvals, evaluate health, and intervene when HITL gates trigger. The dashboard must not impose a heavy frontend build step or require a separate deployment.

The dashboard is served by the same FastAPI process as the API, so it must not add a Node toolchain, a bundler, or a second deployment. Operators use it during incidents, often on the same workstation, which sets the constraints: same JWT dependency as the API, strict CSP, no PII by default, and a bounded polling interval that stays cheap when nobody is looking.

## Decision

1. **FastAPI + Jinja2 + HTMX + Pico.css**: The dashboard is a regular FastAPI route (`/dashboard`) serving Jinja2 templates. No React, no Vue, no build step. Pico.css provides minimal styling (dark mode compatible).

2. **Routes and API endpoints** (see `CONTROL.md` for the full table):
   - `GET /dashboard` → main dashboard page
   - `GET /api/approvals` → pending approvals (polled every 3s via `hx-trigger="every 3s"`)
   - `POST /api/approvals/{id}/action` → approve/reject
   - `GET /api/evals/latest` → last DeepEval run summary
   - `GET /api/sessions/{id}/timeline` → Session Inspector data
   - `GET /api/audit` → paginated audit logs
   - And 9 more (see `CONTROL.md`)

3. **Real-time via WebSocket** (Phase 2): `hx-ext="ws"` upgrades the polling to full-duplex WebSocket for approval queue, worker health, and routing metrics. Fallback to 3s polling if WS connection fails.

4. **Auth same as API**: Dashboard routes protected by `require_roles(["operator", "admin"])`. Same JWT validation. CSRF tokens issued on page load.

5. **Template structure**:
   - `base.html` → HTMX target, CSP, theme toggle
   - `dashboard.html` → main layout with cards: Approvals, Eval Health, Routing Metrics, Worker Health, Security Log
   - Partial templates: `partials/approval_table.html`, `partials/eval_status.html`, etc.

## Consequences

- **Pros**: Zero frontend build dependency; instant refresh via HTMX; familiar HTML/CSS/JS for operators; same auth as API reduces surface area; WebSocket upgrade path.
- **Cons**: HTMX learning curve for developers adding new features; WebSocket requires connection management; Pico.css limits customizability (but that's a feature, not a bug, for security UI).
