# ADR-002: Two-Stage DLP & Reversible Token Vault

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-11

## Context

The gateway must protect against data exfiltration of PII, secrets, and confidential business information. Entity detection must be both fast (sub-50ms) and comprehensive. Real PII must never leave the gateway boundary, and any tokens/values that do reach the model must be sanitized before client delivery.

The gateway runs on CPU inside the Python process, so detection has to fit a sub-50 ms budget for typical prompts and must not require a GPU. Tokens have to stay stable for the life of a session (so multi-turn conversations remain coherent) but must not outlive the conversation, and detokenisation may only happen for the authenticated client — never before a model call or inside an audit record.

## Decision

1. **Stage 1 — Deterministic Presidio scrubber**: `presidio-analyzer` runs on CPU with the `en_core_web_sm` spaCy model and detects `PERSON`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `IBAN_CODE`, `IP_ADDRESS`, `CREDIT_CARD`, `US_SSN` and a local `API_KEY` recognizer (provider tokens such as `sk-…`, `ghp_…`, `AKIA…`, `xox…`, and `api_key = …` assignments). `DLP_ENTITIES` and `DLP_SCORE_THRESHOLD` configure the set and confidence floor. Each accepted span is replaced with a stable session-scoped marker using the Presidio entity type: `{{ENTITY:PERSON_1}}`, `{{ENTITY:EMAIL_ADDRESS_1}}`. Presidio's `AnonymizerEngine` replaces by entity type rather than span, so replacement is performed in `agent/dlp/presidio.py` after analysis. Initialisation is fail-closed: a missing model or import raises `DLPUnavailableError` instead of passing text through.

   **Language contract (2026-11-11).** The NER model is English: `_SPACY_MODELS` in `agent/dlp/presidio.py` maps `en` to `en_core_web_sm`, the only spaCy model in the image, and adding a language means adding its package to `pyproject.toml` and the image plus one entry there. Each prompt is language-detected first with a seeded, offline `langdetect` pass; `DLP_LANGUAGE_MIN_CONFIDENCE` (default `0.80`) is the floor. A confident non-English verdict skips the NER-backed entities — the English model tagged `"donne moi le "` as `PERSON` and corrupted a French prompt — while the pattern recognizers (`EMAIL_ADDRESS`, `PHONE_NUMBER`, `IBAN_CODE`, `IP_ADDRESS`, `CREDIT_CARD`, `US_SSN`, `API_KEY`) keep running in every language because they match shapes, not grammar. A verdict below the floor is analyzed as English, so short English prompts keep full NER coverage. The skip is logged with the detected language, the confidence and the entities that still ran, and `RedactionResult.language` / `RedactionResult.ner_skipped` carry the same facts to the caller. The language-independent recognizers are therefore never gated on detection.

2. **Stage 2 — Semantic sensitivity classifier**: `agent/routing/classifier.py` produces a `CONFIDENTIAL`/`PUBLIC` label with a confidence. A distilled sequence classifier can run through ONNX Runtime (`CLASSIFIER_MODEL_PATH`, a Hugging Face `tokenizer.json`, two logits ordered `[PUBLIC, CONFIDENTIAL]`). When no model is configured, a deterministic weighted-marker classifier covers explicit markings, internal-only notes, codenames, board/HR/finance material, technical IP, customer data and sensitive personal topics. The threshold policy is recorded in ADR-004.

3. **Reversible token vault (Redis)**:
   - `vault:<sha256(session_id)>` maps `{{ENTITY:TYPE_INDEX}}` to `AES-256-GCM(nonce || ciphertext)`; the session id and token are the AEAD associated data, so a ciphertext copied to another session/token fails authentication.
   - `vault:<sha256(session_id)>:rev` stores an HMAC-SHA256 keyed digest of `(entity_type, value) -> token`; repeated values reuse their marker without storing plaintext.
   - `vault:<sha256(session_id)>:seq` supplies per-entity counters.
   - All three keys share the 30-minute `VAULT_TTL_SECONDS`, refreshed when a token is created or restored; `clear(session_id)` expires them immediately.
   - Plaintext is never written to Redis, logs or audit records. Detokenisation happens only for an authorised session via `restore`.

4. **Canary token injection** (implemented in ADR-012): A session-unique `BASTION-CANARY-<uuid4>` string is embedded into the system prompt. If this string — or any token with the configured prefix — appears in model output, the egress filter discards the response, quarantines the session in Redis and writes a `SECURITY_INCIDENT`. Tool output is fenced as `<untrusted_content>` before it reaches the model, and markers are restored only for the vault session derived from `actor_id + conversation_id`.

## Consequences

- **Pros**: PII and provider tokens never touch the model; AES-GCM + AAD prevents ciphertext swapping between sessions/tokens; the HMAC reverse index reuses markers without storing plaintext; semantic classification catches what regex misses; the rule fallback works with no model download; canary detects indirect prompt injection.
- **Cons**: Presidio has a multi-second cold start and tens of milliseconds of warm CPU cost per prompt; the semantic-rule fallback is heuristic and needs tuning against the golden set; the vault requires TTL-based cleanup; canary false positives if a model legitimately echoes system instructions; ADR-012 deliberately has no in-request override, so the session is quarantined until `EGRESS_TRIP_TTL_SECONDS` lapses.
- **Language trade-off**: the DLP language verdict is statistical, not authoritative. Only English ships an NER model, so a name inside a French, German or Italian prompt is not redacted by NER today — it is still scanned by the pattern recognizers and routed by the classifier. A wrong non-English verdict therefore costs NER recall for that prompt without corrupting the text or writing a false `DLP_REDACTION`; a wrong English verdict on foreign text reintroduces the misfire this contract removes, which is why the floor exists. Adding a language model is the path to recovering that recall.
