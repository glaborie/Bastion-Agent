# ADR-002: Two-Stage DLP & Reversible Token Vault

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-11

## Context

The gateway must protect against data exfiltration of PII, secrets, and confidential business information. Entity detection must be both fast (sub-50ms) and comprehensive. Real PII must never leave the gateway boundary, and any tokens/values that do reach the model must be sanitized before client delivery.

The gateway runs on CPU inside the Python process, so detection has to fit a sub-50 ms budget for typical prompts and must not require a GPU. Tokens have to stay stable for the life of a session (so multi-turn conversations remain coherent) but must not outlive the conversation, and detokenisation may only happen for the authenticated client — never before a model call or inside an audit record.

## Decision

1. **Stage 1 — Deterministic Presidio scrubber**: `presidio-analyzer` runs on CPU with the `en_core_web_sm` spaCy model and detects `PERSON`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `IBAN_CODE`, `IP_ADDRESS`, `CREDIT_CARD`, `US_SSN` and four local shape recognizers: `API_KEY` (provider tokens such as `sk-…`, `ghp_…`, `AKIA…`, `xox…`, and `api_key = …` assignments), `ADDRESS` (a street line with a house number followed by a postal code and a place, comma- or newline-separated), `DATE_OF_BIRTH` (a date introduced by an explicit "born"/"date of birth" anchor, in English, French, German or Italian) and `AHV_NUMBER` (a Swiss AHV/AVS number). `DLP_ENTITIES` and `DLP_SCORE_THRESHOLD` configure the set and confidence floor.

   **Swiss AHV/AVS (2026-11-11).** The recognizer matches 13 digits beginning `756` in the dotted (`756.1234.5678.97`), space-grouped (`756 1234 5678 97`) and bare (`7561234567897`) spellings, and validates the EAN-13 check digit (weights 1,3 over the twelve payload digits; the pattern's base score is 0.85, promoted to 1.0 by Presidio when the check passes). It is a `PatternRecognizer` subclass using Presidio's `validate_result` hook, so a checksum-invalid number is dropped and it stays inside the non-English path that keeps only pattern recognizers. The check digit is necessary but not sufficient: `756` is Switzerland's GS1 prefix, so a Swiss EAN-13 product barcode is checksum-valid and also matches. That collision is accepted — the alternative, a format-only match, would redact every 13-digit `756…` reference, and the `sensitive_personal` floor already routes such prompts local — and it is recorded here rather than presented as a semantic test. Each accepted span is replaced with a stable session-scoped marker using the Presidio entity type: `{{ENTITY:PERSON_1}}`, `{{ENTITY:EMAIL_ADDRESS_1}}`. Presidio's `AnonymizerEngine` replaces by entity type rather than span, so replacement is performed in `agent/dlp/presidio.py` after analysis. Initialisation is fail-closed: a missing model or import raises `DLPUnavailableError` instead of passing text through.

   **Language contract (2026-11-11).** The NER model is English: `_SPACY_MODELS` in `agent/dlp/presidio.py` maps `en` to `en_core_web_sm`, the only spaCy model in the image, and adding a language means adding its package to `pyproject.toml` and the image plus one entry there. Each prompt is language-detected first with a seeded, offline `langdetect` pass; `DLP_LANGUAGE_MIN_CONFIDENCE` (default `0.80`) is the floor. A confident non-English verdict skips the NER-backed entities — the English model tagged `"donne moi le "` as `PERSON` and corrupted a French prompt — while the pattern recognizers (`EMAIL_ADDRESS`, `PHONE_NUMBER`, `IBAN_CODE`, `IP_ADDRESS`, `CREDIT_CARD`, `US_SSN`, `API_KEY`) keep running in every language because they match shapes, not grammar. A verdict below the floor is analyzed as English, so short English prompts keep full NER coverage. The skip is logged with the detected language, the confidence and the entities that still ran, and `RedactionResult.language` / `RedactionResult.ner_skipped` carry the same facts to the caller. The language-independent recognizers are therefore never gated on detection.

2. **Stage 2 — Semantic sensitivity classifier**: `agent/routing/classifier.py` produces a `CONFIDENTIAL`/`PUBLIC` label with a confidence. A distilled sequence classifier can run through ONNX Runtime (`CLASSIFIER_MODEL_PATH`, a Hugging Face `tokenizer.json`, two logits ordered `[PUBLIC, CONFIDENTIAL]`). When no model is configured, a deterministic weighted-marker classifier covers explicit markings, internal-only notes, codenames, board/HR/finance material, technical IP, customer data and sensitive personal topics. The threshold policy is recorded in ADR-004.

3. **Reversible token vault (Redis)**:
   - `vault:<sha256(session_id)>` maps `{{ENTITY:TYPE_INDEX}}` to `AES-256-GCM(nonce || ciphertext)`; the session id and token are the AEAD associated data, so a ciphertext copied to another session/token fails authentication.
   - `vault:<sha256(session_id)>:rev` stores an HMAC-SHA256 keyed digest of `(entity_type, value) -> token`; repeated values reuse their marker without storing plaintext.
   - `vault:<sha256(session_id)>:seq` supplies per-entity counters.
   - All three keys share the 30-minute `VAULT_TTL_SECONDS`, refreshed when a token is created or restored; `clear(session_id)` expires them immediately.
   - Plaintext is never written to Redis, logs or audit records. Detokenisation happens only for an authorised session via `restore`.

4. **Canary token injection** (implemented in ADR-012): A session-unique `BASTION-CANARY-<uuid4>` string is embedded into the system prompt. If this string — or any token with the configured prefix — appears in model output, the egress filter discards the response, quarantines the session in Redis and writes a `SECURITY_INCIDENT`. Tool output is fenced as `<untrusted_content>` before it reaches the model, and markers are restored only for the vault session derived from `actor_id + conversation_id`.

5. **A DLP hit keeps the request on the local model (2026-11-11, IDEA-017).** Redaction is the control that lets a prompt reach a third-party provider, so it may only be trusted as far as its recall. On 2026-11-11 a prospect record (name, street, city, phone, email, date of birth) reached `cloud-primary` as `PUBLIC`: only the phone and the email were tokenised, the out-of-vocabulary name was never tagged `PERSON`, and the address and birth date were outside the entity list. The classifier was not wrong — it models corporate confidentiality and harm, not personal data — and the corpus encodes that, with PII rows carrying `expected_label: null`.

   Two changes follow, and neither rewrites the classifier's verdict:

   - **Route override.** `ModelRouter.route/aroute` accept `pii_detected`; when the DLP stage redacted at least one entity, the request goes to `local-llama` even when the label is `PUBLIC`, and `RouteDecision.override = "pii_detected"` records why. The `ROUTING_DECISION` audit row keeps the original label, reason and confidence next to the override, and the server span carries `bastion.route.override`, so "PUBLIC, kept on-box because DLP found personal data" is legible after the fact. The rule is deliberately a proxy: if the stage found *any* personal data in the prompt, its recall on the rest of the prompt is not trusted. A local-model failure on an overridden request fails closed with `503` and a `SECURITY_INCIDENT` (`pii_route_local_unavailable`), never a cloud fallback (ADR-004).
   - **Two narrow recognizers instead of Presidio's generic types.** `LOCATION` and `DATE_TIME` are not enabled: measured over ADR-006's corpus on 2026-11-11 they fire on 19 of 86 rows, labelling `UDP`, a GitHub token and `the board minutes` as places or dates and redacting benign prompts. `ADDRESS` and `DATE_OF_BIRTH` are shape-anchored instead — a street + house number + postal code + place, and a date preceded by its own birth anchor — and are registered per modelled language so they keep working when the NER pass is skipped. The address pattern disables case-insensitivity locally (`(?-i:…)`) because Presidio compiles recognizer patterns with `re.IGNORECASE`, which otherwise lets the street match swallow the words before it.

   The residual boundary is honest and recorded: an out-of-vocabulary name is still not redacted, so it travels to `local-llama` in plaintext. That is acceptable because the local model is on the operator's hardware; it would not be acceptable on a cloud route, which is exactly what the override prevents.

## Consequences

- **Pros**: PII and provider tokens never reach a third-party model (redacted, and any prompt where DLP finds personal data is kept on the local model); AES-GCM + AAD prevents ciphertext swapping between sessions/tokens; the HMAC reverse index reuses markers without storing plaintext; semantic classification catches what regex misses; the rule fallback works with no model download; canary detects indirect prompt injection.
- **Cons**: Presidio has a multi-second cold start and tens of milliseconds of warm CPU cost per prompt; the semantic-rule fallback is heuristic and needs tuning against the golden set; the vault requires TTL-based cleanup; canary false positives if a model legitimately echoes system instructions; ADR-012 deliberately has no in-request override, so the session is quarantined until `EGRESS_TRIP_TTL_SECONDS` lapses.
- **Language trade-off**: the DLP language verdict is statistical, not authoritative. Only English ships an NER model, so a name inside a French, German or Italian prompt is not redacted by NER today — it is still scanned by the pattern recognizers, routed by the classifier, and kept off the cloud as soon as any recognizer fires. A wrong non-English verdict therefore costs NER recall for that prompt without corrupting the text or writing a false `DLP_REDACTION`; a wrong English verdict on foreign text reintroduces the misfire this contract removes, which is why the floor exists. Adding a language model is the path to recovering that recall.
- **PII-routing trade-off**: the override is a proxy, not a recall measurement. A prompt with personal data costs local-model latency and quality even when redaction was complete (an email address alone is enough), and a prompt whose only personal data Presidio cannot see — an out-of-vocabulary name with no other entity — still takes the classifier's route. The guarantee is therefore "anything we can detect stays on-box", not "nothing personal ever leaves"; the managed path to closing the rest is a PII-specific model or a dedicated address/name recognizer, which is why `ADDRESS` and `DATE_OF_BIRTH` were added narrowly rather than enabling Presidio's generic `LOCATION`/`DATE_TIME`.
