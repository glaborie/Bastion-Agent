# ADR-014: Observability & Trace Privacy

**Status:** Accepted  
**Date:** 2026-11-11  
**Last modified:** 2026-11-11

## Context

The gateway and the worker are the only two producers of telemetry, and both emit OTLP/HTTP spans to one local OpenTelemetry Collector. That pipeline is the system's second record of what happened: the audit ledger proves *that* a turn occurred and stores a hash of it, while a trace carries the timings, the guardrail verdicts and the model usage that make an incident diagnosable. It is also the only output that leaves the host in a form a third party can read, so what a span may contain is a privacy decision in the same sense as the DLP stage's entity list.

Until now the rule existed only in `telemetry.py` docstrings and the README: the exclusion list, the "never payload text" contract and the overlay procedure were incidental code, not a recorded decision. A reviewer could not tell a deliberate omission from an unfinished feature, and a future change could export prompt text or delete `DEFAULT_EXCLUDED_URLS` without contradicting anything written down. The collector's configuration is load-bearing too — it decides which fields a metered backend receives and drops the span classes an unauthenticated caller can inflate.

The constraints are deployment reality. Two processes share one stateless collector, so all egress policy lives in configuration rather than in either application. Backends are interchangeable and metered — Langfuse and Arize charge per event, and one client polling a route the gateway does not implement once sent about 11,500 dropped spans a day to Arize — so a checkout with no credentials must export locally by default. And because the collector reads its configuration at start, changing the destination is a container recreate, not a code change.

## Decision

1. **Topology: two producers, one collector.** `gateway/main.py` and `agent/runtime.py` call `telemetry.configure_tracing(settings)` at startup, which installs one `TracerProvider` with a `BatchSpanProcessor` (queue 2048, 2 s delay, 10 s export timeout) and an `OTLPSpanExporter` pointed at `OTEL_EXPORTER_OTLP_ENDPOINT` (normalised to `/v1/traces` by `telemetry.traces_endpoint`). Spans travel over OTLP/HTTP to the `otel-collector` service on port 4318; the collector also listens for gRPC on 4317 and publishes both on loopback only. The resource carries `service.name` (`bastion-gateway` or `bastion-worker`), `service.version`, `service.namespace=bastion-agent` and `deployment.environment`. `instrument_app` adds ASGI server spans; `instrument_http_client` is applied to the OmniRoute client alone, so the Keycloak JWKS and token calls are not traced. `shutdown_tracing` flushes the provider at shutdown. `OTEL_ENABLED=false` disables the pipeline entirely and is the supported way to run without a collector.

2. **The collector owns egress, and an overlay selects it.** `config/otel/otel-collector-config.yaml` is the only definition of receivers, processors, exporters, headers and retry policy. `docker-compose.yml` passes it as the first `--config` and mounts the file named by `OTEL_REMOTE_EXPORT_CONFIG` at `/etc/otelcol/export.yaml` as the second. Maps merge across the two files while a list replaces the same path, so the overlay owns exactly one thing: `service.pipelines.traces.exporters`. The overlays are `otel-collector-no-export.yaml` (the default: `[debug]`, nothing leaves the host), `otel-collector-openlit.yaml` (debug plus the self-hosted, unmetered OpenLit) and `otel-collector-export.yaml` (debug plus Langfuse Cloud and Arize AX). Changing the destination is `OTEL_REMOTE_EXPORT_CONFIG=<overlay>` followed by `docker compose up -d --force-recreate otel-collector`; switching back to `otel-collector-no-export.yaml` stops egress and means the remote exporters' credentials are never read. **The overlay in force is runtime configuration, not architecture**: no code path, image or test depends on which one is mounted, and an exhausted backend quota is handled in `.env`, not in a commit.

3. **Attribute allow-list, and fields that are never exported.** Spans carry machine metadata only: `gen_ai.conversation.id` and `bastion.conversation.id`; request shape (`bastion.request.messages`, `bastion.request.chars`); the DLP verdict (`bastion.dlp.redacted`, `bastion.dlp.entities`, `bastion.dlp.types`); the routing verdict (`bastion.classification`, `.reason`, `.confidence`, `bastion.route`, `bastion.route.local`, `bastion.route.override`); the egress verdict (`bastion.egress.blocked`, `.reason`, `.restored_tokens`, `.unresolved_tokens`); the model usage conventions (`gen_ai.operation.name`, `gen_ai.system`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.request.temperature`, `gen_ai.request.max_tokens`, `gen_ai.response.finish_reasons`, `gen_ai.usage.input_tokens`, `.output_tokens`, `.total_tokens`, `.cost`, `bastion.model.swapped`); tool and approval identity (`bastion.tool.name`, `bastion.audit.session_id`, `bastion.tool.status`, `bastion.tool.code`, `bastion.approval.ticket_id`, `bastion.demo.run_id`, `bastion.demo.scenario`); and the HTTP status/route the instrumentors add. **Never exported**: prompt text, completion text, tool arguments, tool output, vault markers and their plaintext, and per-user identity (subject, username, email, the actor id). `telemetry.annotate_span` and `span_attributes` are the single seam for this, and they drop unset values rather than sending `None`. The auditable record of content is the hash-chained ledger (ADR-005); the trace records the verdict, never the payload.

4. **Exclusions, sampling and volume.** `DEFAULT_EXCLUDED_URLS` (`/health`, `/health/ready`, `/metrics`, `api/evals/latest$`) keeps health probes and the dashboard's 30 s evaluation poll out of tracing, because they are pure quota consumption with no diagnostic value. The former `api/approvals$` exclusion is gone: ADR-007 pushes the queue over `/ws/approvals`, so a fallback `GET /api/approvals` and the four-eyes decision `POST /api/approvals/<ticket>/action` are both worth a span. `OTEL_TRACES_SAMPLER_RATIO` sets a `ParentBased(TraceIdRatioBased)` root sampler, default `1.0`; `0` disables recording with a warning and is not a silent no-op. The worker traces jobs only: the two cron sweeps (`expire_stale_approvals_job`, `resume_approved_tickets_job`, every 30 s) create no span, so their noise never reaches a backend. At the collector, `filter/noise` drops ASGI `http send`/`http receive` event spans and 404 server and client spans before the exporters, so the dropped set is identical for the `debug` exporter and for every remote backend; path scans belong at the proxy, not in a paid trace store.

5. **Backends are interchangeable, by configuration only.** OpenLit, Langfuse and Arize differ solely in an exporter block in the base config and one entry in the overlay's exporter list. Langfuse needs `Basic base64("<public_key>:<secret_key>")` in `LANGFUSE_OTLP_AUTH` and the ingestion version header; Arize needs the base host (the exporter appends `/v1/traces` itself), JSON encoding with compression disabled (their ingest does not gunzip), and `space_id` / `api_key` / `x-project-name`; OpenLit is a local OTLP/HTTP endpoint reached through `host.docker.internal`. Adding a backend is a new exporter plus an overlay, with no change to `telemetry.py`, `gateway/` or `agent/`. `tests/test_otel_config.py` pins the base-owns-settings / overlay-owns-exporters pairing, and `tests/test_telemetry.py` pins the exclusion list, the attribute filtering and the client instrumentation.

6. **Tracing never fails a request.** Export is asynchronous and best effort: a collector outage, a rejected batch or an exhausted quota is logged by the SDK and the HTTP request completes. Tracing is observability, not a security control, so there is no fail-closed path here — the controls that must fail closed are the DLP, routing and egress stages (ADR-002, ADR-004, ADR-012), and none of them reads a span to make a decision.

## Consequences

- **Pros**: One place (`telemetry.py` plus `config/otel/`) defines what leaves the host and where it goes, so the trace-privacy rule is reviewable rather than implicit; the payload-free contract means traces can go to a third party without moving the leak the DLP stage exists to stop; a backend can be swapped, muted or added without touching application code; the exclusion list and the collector filter keep dashboard polling, cron sweeps and path scans from inflating a metered quota; the fail-open exporter keeps an observability outage from becoming a service outage.
- **Cons**: Debugging content-level problems needs the audit ledger and the vault, because the trace deliberately lacks the text; the allow-list is maintained by hand, so a new attribute is exported unless the author checks this ADR; the overlay mechanism is split across two files and a recreate, and a typo in `OTEL_REMOTE_EXPORT_CONFIG` mounts the wrong file rather than failing loudly; the `debug` exporter and the remote exporters share one pipeline, so a noisy processor change is visible to every destination at once; backend-specific quirks (Arize's no-gzip, Langfuse's auth header) live in collector configuration and are only exercised when that overlay is mounted.
