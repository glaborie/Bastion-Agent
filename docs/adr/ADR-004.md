# ADR-004: OmniRoute Model Routing & Failover

**Status:** Accepted  
**Date:** 2026-11-09  
**Last modified:** 2026-11-19

## Context

The agent needs to route prompts to the correct model backend depending on sensitivity, cost, and availability. There must be a local fallback (RTX 3060 Ti) for confidential prompts, and cloud providers for general use. Provider failover must be transparent to the agent code.

The local backend is a single RTX 3060 Ti with 8 GB of VRAM: Qwen 2.5 7B at Q4_K_M plus an 8k context fits, but only one request can be in flight, so local capacity is scarce. OmniRoute keeps its routing state in SQLite rather than a declarative file, and every service is bound to loopback on this host. The trade-offs are an extra network hop on every completion and one more stateful component to back up.

## Decision

1. **OmniRoute as the single upstream endpoint**: The FastAPI gateway and ARQ worker send all chat completions to `http://omniroute:20128/v1/chat/completions` (OmniRoute listens on 20128; the gateway owns 8000). No direct `openai` or `anthropic` SDK calls from agent code. The `/v1` plane requires the bearer credential in `OMNIROUTE_API_KEY` (`REQUIRE_API_KEY=true`).

2. **Model alias routing**: The agent sets the `model` field in the chat completion payload:
   - `model: "local-llama"` → OmniRoute dispatches to `llama.cpp` (RTX 3060 Ti, Qwen 2.5 7B Q4_K_M, served under the alias `qwen2.5-7b-instruct-q4_k_m`). Single target, **no fallback**.
   - `model: "cloud-primary"` → OpenRouter, as a `priority` combo: `openai/gpt-4o-mini` first, `anthropic/claude-haiku-4.5` on failure. There is no separate `cloud-fallback` alias; failover is internal to the combo.
   - `model: "cloud-strong"` → OpenRouter, the same two providers in the opposite priority: `anthropic/claude-haiku-4.5` first, `openai/gpt-4o-mini` on failure. Decision 3 selects it for PUBLIC prompts that read as hard work. Tiering introduces no new provider or model id, only a second ordering of the two already trusted here.

3. **Routing policy via classifier**: The classifier in `agent/routing/classifier.py` tags each prompt `CONFIDENTIAL` or `PUBLIC`. `CONFIDENTIAL` is only assigned when the classifier is confident (score ≥ `CLASSIFIER_CONFIDENCE_THRESHOLD`, default 0.55); everything below the threshold is treated as `PUBLIC`:
   - `CONFIDENTIAL` → `model: "local-llama"`.
   - `PUBLIC` (including borderline) → `model: "cloud-primary"`.

   One deterministic exception exists and it never rewrites the verdict: when the DLP stage redacted at least one entity, the request goes to `local-llama` even if the label is `PUBLIC`, and `RouteDecision.override = "pii_detected"` records why alongside the unchanged label, reason and confidence. The rule and its residual boundary are ADR-002 decision 5.

   **Tier policy (2026-11-17, IDEA-028).** This decision previously ignored the
   cost input its own Context names: a one-line lookup and a multi-step analysis
   both went to `cloud-primary`. PUBLIC prompts are now split by a complexity
   verdict that is separate from, and subordinate to, the sensitivity verdict:

   - `agent/routing/complexity.assess_complexity` reads the same raw text the
     classifier reads and scores it `0.0`-`1.0` from two components: named
     markers (`step_by_step`, `enumerated_items`, `multi_question`,
     `code_block`, `analysis_verb`, `trade_offs`; each counts once) weighted
     `0.7`, and prompt length weighted `0.3`, which ramps from 40 to 160 words
     and saturates. Two distinct markers reach a full marker score.
   - At or above `COMPLEXITY_THRESHOLD` (default `0.6`) the prompt is `COMPLEX`
     and goes to `MODEL_CLOUD_STRONG_ALIAS` (`cloud-strong`); below it the
     prompt is `SIMPLE` and goes to `MODEL_CLOUD_ALIAS` (`cloud-primary`). The
     threshold is the single control point: `1.0` disables tiering.
   - The verdict is **subordinate**. `CONFIDENTIAL` still routes `local-llama`,
     and a DLP hit still routes `local-llama` with `override = "pii_detected"`
     whatever the complexity score says. Complexity is computed and recorded
     either way — the ledger and the span keep it next to the label it did not
     change — but the alias it would have chosen is discarded for a local
     route, so no complexity verdict can move a confidential or PII-bearing
     prompt off the host. This is the honest boundary of the change: a misroute
     is a cost or quality regression and never a confidentiality one.
   - The `ROUTING_DECISION` row carries `complexity` and `complexity_score`
     beside `route`, and the server span carries `bastion.complexity` and
     `bastion.complexity.score` (ADR-014 decision 3). Neither carries prompt
     text.

   **Measured sample (2026-11-17).** A 9-prompt sample was routed through
   `ModelRouter` against the live OmniRoute and completed once each
   (`max_tokens=256`): the four `SIMPLE_PROMPTS` and four `COMPLEX_PROMPTS`
   fixtures in `tests/test_routing_complexity.py`, plus one 200-word unmarked
   paste of the word `clause`. The distribution is 5 `SIMPLE` → `cloud-primary`
   and 4 `COMPLEX` → `cloud-strong`; the 200-word paste stays `SIMPLE` as
   designed, because length alone is 0.3 of a 0.6 threshold. Per-turn
   `usage.cost` medians: `cloud-primary` $0.00000936 (n=5), `cloud-strong`
   $0.00129492 (n=4), whole sample $0.00006059 (n=9). The strong tier is about
   138x the cheap tier per turn on this sample, which is the honest shape of the
   trade: it is spent only on prompts that carry at least two independent
   complexity markers, and lowering `COMPLEXITY_THRESHOLD` spends it on more
   traffic. The sample is small and was not labelled by a human; it measures the
   cost of the tier split, not the quality gain, which no gate here evaluates.

   The classifier is either a two-logit ONNX model (`[PUBLIC, CONFIDENTIAL]`, loaded with a Hugging Face `tokenizer.json`) or, when `CLASSIFIER_MODEL_PATH` is unset, a deterministic weighted-marker fallback whose confidence is `weight / (weight + 2)`. This is a deliberate cost trade-off: the scarce local GPU is reserved for prompts the classifier positively identifies as confidential, while ambiguous traffic uses the cheaper cloud path. The threshold is the single control point for that trade-off; lowering it routes more traffic locally.

4. **Health checks & circuit breaking**: OmniRoute monitors upstream health and exposes `/api/health` (used by the container healthcheck). Cloud models fail over within `cloud-primary`; `local-llama` has no cloud target, so a `llama.cpp` outage fails closed with an error rather than silently sending confidential prompts to a third party. Availability is recovered by restoring the local backend. The agent client (`agent/routing/client.py`) retries only idempotent connection failures and 408/429/5xx responses, always with the **same** alias; it never switches a confidential prompt to another alias.

   **Latency budget & per-route availability (2026-11-19, IDEA-073).** A slow
   upstream must not consume the worker, so a turn is bounded in time and a
   sick route is bounded in concurrency:

   - `gateway.routers.chat.run_turn` starts one `RequestDeadline` from
     `REQUEST_DEADLINE_SECONDS` (default 280 s, below the worker's 300 s
     `job_timeout`). It is checked before ingress, DLP, routing, handoff,
     preflight, the model call, egress and delivery, and before every retry. An
     expired budget raises `DeadlineExceededError`, which the gateway maps to
     `504`; it never becomes another attempt.
   - The retry budget is the time that remains, not only a count: an attempt is
     retried only when the remaining budget covers its backoff, and the attempt's
     HTTP timeout is the smaller of `OMNIROUTE_TIMEOUT_SECONDS` and that
     remaining budget. `OMNIROUTE_MAX_RETRIES` still caps the attempts, so a hung
     upstream is cut off at the deadline instead of after
     `timeout × (retries + 1)`.
   - Each alias has a bulkhead of `OMNIROUTE_MAX_CONCURRENCY` (default 2)
     in-flight calls. The `N+1` call is refused immediately with `503` rather
     than queueing behind a hung upstream. Counters are per alias, so a stalled
     `local-llama` cannot consume the cloud budget or vice versa.
   - Each alias has an availability breaker: after
     `OMNIROUTE_BREAKER_FAILURE_THRESHOLD` (default 3) consecutive timeouts/5xx
     it opens and answers `503` without contacting upstream, allows one half-open
     probe after `OMNIROUTE_BREAKER_COOLDOWN_SECONDS` (default 30) and closes on
     that probe's success. A 4xx resets the consecutive count because the route
     answered. The breaker only refuses a call; it never rewrites the alias, so a
     `CONFIDENTIAL` or PII-bearing prompt still fails closed instead of moving.

5. **OmniRoute config externalized**: OmniRoute persists its state in SQLite, so `config/omniroute/config.yaml` is the declarative contract (provider node, connections, combos) applied idempotently by `scripts/omniroute_bootstrap.py`:
   - provider node `openai-compatible-chat-local`: `http://llama-cpp:8080/v1`, prefix `llama`, credential from `LLAMA_API_KEY`;
   - connection `openrouter`: `https://openrouter.ai/api/v1`, credential from `OPENROUTER_API_KEY`;
   - combos `local-llama` (priority, one local target), `cloud-primary` (priority, `gpt-4o-mini` first) and `cloud-strong` (priority, `claude-haiku-4.5` first);
   - gateway API key stored in `OMNIROUTE_API_KEY`.

   Re-running the bootstrap after `docker compose down -v` restores the whole routing plane and smoke-tests both aliases.

## Consequences

- **Pros**: Agent code is completely provider-agnostic; switching models is a config change, not a code change; confidential traffic never leaves the host and fails closed rather than falling back to cloud; retries are bounded and never cross aliases; PUBLIC traffic is tiered by a verdict recorded beside the label it did not change, so the routing row and the span explain both what the prompt was and which model the tier bought; one slow or dead route is bounded in time and concurrency, so it fails fast instead of consuming the worker.
- **Cons**: A local inference outage is an outage (no cloud fallback by design); one more moving part (OmniRoute); requires managing API keys for cloud providers; latency added by the extra routing hop; the PII override sends more traffic to the scarce local GPU, and a prompt with personal data waits on the local model even when redaction was complete; the complexity signal is a marker heuristic, so a short prompt that hides its difficulty behind plain wording is served by the cheap model, and the sample above shows the strong tier costs two orders of magnitude more than the cheap one; the deadline, bulkhead and breaker are per process, so each gateway replica keeps its own counters and an open breaker is local knowledge rather than a cluster-wide verdict.
