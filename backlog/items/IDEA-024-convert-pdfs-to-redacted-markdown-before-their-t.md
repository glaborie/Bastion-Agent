### IDEA-024: Convert PDFs to redacted Markdown before their text reaches a model

- status: inbox
- priority: P2
- phase: v0.4
- area: agent
- tags: pdf, markitdown, dlp, ingestion, pii
- depends-on: -
- spec: -
- created: 2026-11-11
- updated: 2026-11-11
- source: session request on 2026-11-11 ("create a tool to convert pdf as markdown with PII redaction before sharing with a LLM; use an existing tool such as microsoft/markitdown")

**Problem**

Bastion has no document path. `ChatRequest` (`gateway/routers/chat.py:94-104`) accepts only `ChatTurn.content: str` with `extra="forbid"` under `MAX_MESSAGE_CHARS` 32_768 and `MAX_TOTAL_CHARS` 65_536, no router in `gateway/routers/` takes a multipart body, and the two text entry points in the tool catalog (`read_file`, `execute_file_write` in `docs/tools/v1.json`) are UTF-8 only, so a PDF can only enter the pipeline by copy-paste — which loses headings, tables and page boundaries — or through a converter outside the perimeter, whose unredacted output never reaches `PresidioDLP.redact()` (`agent/dlp/presidio.py:442`) and never appears in the ledger. `pyproject.toml` pins no document parser at all, and the obvious library is not a redaction step: `markitdown` (microsoft/markitdown) sends the raw PDF to Azure Document Intelligence when `docintel_endpoint` is configured, and its OCR ships as a separate `markitdown-ocr` package that requires an `llm_client`, so either option puts the whole file or its page images in front of a model before any PII is replaced. The missing piece is therefore a one-way gate, not a library call: conversion has to happen inside the perimeter, before the text exists anywhere else.

**Outcome**

One documented local command (`docker compose exec gateway python -m agent.ingest.cli <file.pdf> --tenant <id> --actor <sub> --output <path.md>`, or the same module under `uv run` on the host) writes a Markdown artifact in which every entity the shipped DLP stage detects is already a vault marker, plus a report naming the extractor, the page count and the entity types and counts — never a plaintext value. The adapter is thin and closed: `markitdown[pdf]` pinned, `MarkItDown(enable_plugins=False)`, no `docintel_*` argument and no `llm_client`, PDF as the only accepted extension and magic number, a size ceiling and a parse timeout read from settings, and any encrypted, corrupt, oversized, mislabelled or zero-text file exits non-zero having written no artifact. PDF metadata and embedded attachments never reach the artifact; markers are scoped to a session derived from tenant, actor and the input digest so two documents cannot share them; and the documentation states plainly that a de-identified document is still confidential by content and still needs the classifier's route — this is de-identification, not declassification.

**Acceptance**

- [ ] `uv run pytest tests/test_document_ingest.py -q` converts a committed fixture PDF whose text carries a person name, an email and an IBAN, and asserts the artifact contains the three `{{ENTITY:...}}` markers, contains none of the three plaintext values, and contains neither the fixture's `/Author` nor its `/Title` metadata string
- [ ] Fail-closed, each case writing no output file and exiting non-zero: an encrypted PDF, a truncated PDF, a PNG renamed to `.pdf`, a file over the size ceiling, and an image-only PDF that yields no text — all five covered in `tests/test_document_ingest.py` against a temporary output path, so a pre-existing file is not overwritten either
- [ ] The conversion cannot reach the network: an httpx request recorder observes zero outbound requests during a conversion, and a test asserts the adapter constructs `MarkItDown(enable_plugins=False)` with no `docintel_endpoint`, no `docintel_credential` and no `llm_client`, and that no settings key exists for any of them
- [ ] The redactor is the shipped `PresidioDLP.redact()` with a tenant and a session, not a second implementation: a test passes the same text through the module and through `redact()` and asserts byte-identical markers, and asserts no plaintext value or model-bound text appears in the run's log records
- [ ] Restore is scoped and honest: markers restore only for the same tenant and session, a different tenant or session leaves them untouched, and once the 30-minute `VAULT_TTL_SECONDS` (1800) lapses the command reports the markers as expired instead of printing them unchanged — all three asserted, using the fakeredis TTL path the vault tests already use
- [ ] `markitdown[pdf]` is pinned in `pyproject.toml` (the narrow extra, not `[all]`) with `uv.lock` regenerated, the adapter lives in one module (`agent/ingest/document.py`) with the extractor injectable behind a protocol, and `mypy` and `pylint` stay clean
- [ ] The size ceiling and the parse timeout are settings keys with documented defaults in `.env.example`, and a test with a deliberately slow extractor proves the timeout aborts the run and writes no artifact
- [ ] `README.md` documents the command, the PDF-only input allow-list, the 30-minute restore window and the de-identification boundary sentence, and the ingestion trust boundary (untrusted binary parser in-process, format allow-list, extraction-failure policy, no OCR or Document Intelligence in this slice) is recorded in `docs/adr/ADR-002.md` or a new ADR; `uv run python scripts/check_adrs.py` passes
- [ ] No new surface ships with it: `grep -rn "markitdown" docs/tools/v1.json docker-compose.yml gateway/` returns nothing, `docker compose config` is unchanged, and no gateway route, compose service or `.env` key becomes required

- `spec: -` is deliberate: the gap is that no ADR governs a document ingestion boundary, so the item's first deliverable is that decision. Amending ADR-002 is only correct if the entity list or analyzer contract changes, which this slice does not require.
- Classification: `P2`/`v0.4`. New capability with no stated invariant broken and no live incident, and ADR-008 decision 5 freezes features inside a phase while the current phase is `v0.2`, so it is not `P0`/`P1`. No ADR-008 line names document ingestion; `v0.4` "adaptive DLP" is the nearest pipeline home because this is a new content path into the same DLP stage, `v0.6` "custom DLP adapters" is the fair alternative, and triage may move it to either without changing the item. `area: agent` because the load-bearing part is a stage beside `agent/dlp` and `agent/egress`; `tooling` fits only if it stays a standalone command, `gateway` only once an upload route exists.
- Decisions deliberately not taken: whether the entry point is a module (`python -m agent.ingest.cli`, which works inside the image because `Dockerfile:36-38` copies `agent/` but not `scripts/`) or a `scripts/` file plus a Dockerfile line; whether the artifact keeps reversible vault markers (restorable for 30 minutes) or irreversible placeholders such as `[PERSON_1]`, which is the safer default for a document leaving the perimeter but loses the restore path; whether a conversion writes an audit row (the `AuditEventType` vocabulary is frozen per ADR-007 decision 7, so a new member is its own decision), a structured log only, or both; and whether the CLI merely prints the classifier verdict or refuses to emit an artifact for a `CONFIDENTIAL` document whose destination is a cloud model.
- Honest limits to record rather than paper over: the parser runs in-process on an untrusted file with no sandbox in this slice, and the size ceiling, format allow-list and parse timeout bound resource use but not a parser vulnerability; markitdown's OCR path requires an `llm_client` and is excluded for the reason above, so a scanned PDF is refused instead of being read; a damaged PDF may still yield partial text, so the zero-text check catches the empty case only and a page-count-versus-extracted-characters floor is worth adding; and the redaction inherits the DLP recall boundary — an out-of-vocabulary name or a postal address behaves here exactly as it does in chat (IDEA-017), which the README must not overclaim.
- Deliberately out of scope: DOCX/XLSX/PPTX/HTML/EPUB inputs, OCR and redaction of text inside images or embedded EXIF, a gateway upload endpoint or an attachment field on `ChatRequest`, automatic insertion of the artifact into a chat turn, batch corpus conversion, and a golden-corpus row (the eval gate is prompt-level). `markitdown[all]` is also out: each extra widens the parser surface for no benefit while PDF is the only accepted type.
- Intake only: no dependency, `pyproject.toml`, code, test, doc or ADR change is part of this capture.
