### IDEA-041: Store backlog items one per file so parallel branches never conflict

- status: active
- priority: P2
- phase: v0.3
- area: tooling
- tags: backlog, git, concurrency, ci
- depends-on: -
- spec: ADR-008
- created: 2026-11-13
- updated: 2026-11-13
- source: session request on 2026-11-13, review of the backlog machinery after repeated PR conflicts on BACKLOG.md

**Problem**

Every branch edits the single `BACKLOG.md`, and roughly 95% of its 2212 lines are the generated `## Board` and `## Index` (lines 16-124), which inline every item's status, so any item change rewrites the whole file and two branches in flight conflict on every pull request inside generated content. `scripts/check_backlog.py:533-535` rewrites the file from a snapshot (`read_text` then `path.open("w")`, truncating, no lock, no atomic rename), so two writers in one checkout lose an item silently instead of failing. `next-id` (`BACKLOG.md:14`) is a per-worktree counter, so two branches allocate the same id and the collision surfaces only at merge, and the one edit an agent must make every session (`status: active`, written by `scripts/dev/worktree.sh:104-124`) is in the most contended file in the repository.

**Outcome**

`backlog/items/IDEA-NNN-<slug>.md` holds one item each with a byte-identical body, `backlog/config.toml` holds `current-phase` and `wip-limit`, and `BACKLOG.md` becomes an index regenerated by `check_backlog.py --write` from those files. A branch touches only its own item file, so no two branches edit the same path. Capture allocates the next id from `origin/master` and creates the file with `O_EXCL`; a duplicate id that still reaches merge is a different file, so git merges cleanly and the validator names it (renumber by `git mv`). `scripts/dev/worktree.sh` marks an item active by editing only that item's file, and the intake skill, `/idea`, `/next`, the `backlog` subagent config and `AGENTS.md` point at the new layout.

- Open question for triage: whether the rendered `BACKLOG.md` stays committed. If it does, a capture branch still modifies it and the conflict moves rather than disappears — resolution becomes "re-run `--write`" instead of a semantic merge, which is much cheaper but not zero. Generating it on demand and gitignoring it removes the conflict entirely at the cost of a reader needing the script; the item does not decide this and the acceptance only requires the render to be deterministic.
- Related but deliberately separate: the id collision is only fully solved if capture reads `origin/master` rather than the worktree, which is a discipline the skill must state (it cannot be enforced by the script alone). Fixing it inside one worktree is the `O_EXCL` half; the "allocate from the remote" half is documentation in the intake skill.
- `spec: ADR-008` names the record that makes `BACKLOG.md` the legal destination for ideas (decisions 4-5), so amending it is part of the change; no ADR decides the file layout itself.
- Intake only: no script, test, `.opencode` config, `AGENTS.md` or ADR change is part of this capture, and the idea was not implemented in the turn that produced it.
